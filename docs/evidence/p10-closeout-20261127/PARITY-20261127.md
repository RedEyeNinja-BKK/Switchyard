# Node registry parity — method and result, 2026-11-27

Question: `GET /v1/api/models` returned 22,920 B from `head` and 22,924 B from each of
`worker_2…5`. Is that a real configuration difference between nodes?

Answer: **no.** It is an artefact of the MCP bridge's response envelope, not of the registry and not
of the registry's serialization.

## Method (all read-only)

1. **Storage topology.** `/etc/turnstone/config.toml` is shared by all five units and names one
   PostgreSQL DSN. `turnstone-server.service` (head, :8080) and `turnstone-node@2..5` (:8082–:8085)
   therefore read the same `model_definitions` table. Read inside
   `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ, READ ONLY`; connection rolled back.
2. **Settings scope.** `system_settings` has a `node_id` column and 17 rows; every row carries
   `node_id = ''`, i.e. global. The five extra fields the endpoint appends (`default_alias`,
   `channel_default_alias`, `judge_default_alias`, `stt_default_alias`, `tts_default_alias`) resolve
   from these rows plus the registry, identically on every node.
3. **Per-node self-report.** `node_metadata` key `models` — the list each node publishes about
   itself — is 9,879 B with `sha256 cd05d5fcf2a88c4d…` and 91 entries on all five nodes
   (`turnstone-head-1`, `turnstone-node-2..5`), byte-identical.
4. **Envelope arithmetic.** `/opt/turnstone-integrations/self-admin/server.py::_emit` builds
   `json.dumps({"status":…,"receipt":…,"body":…}, separators=(",",":"))` and, above
   `MAX_RETURN = 18000`, reports `length = len(envelope)` (measured 2026-11-27). The receipt contains
   `"target"`. `len("worker_2") - len("head") = 4`. Receipt ids (32), timestamps (20), digests (64),
   method, path, status and `self_guard` are fixed-width, so the target name is the only variable.
5. **Control on the same endpoint.** On `head`, `/v1/api/_internal/model-status` = 26,790 B; with
   `?alias=smart` (12 characters) = 26,802 B; with `?limit=5&offset=0` (17 characters) = 26,807 B.
   The response handler ignores query parameters, so the body is unchanged and the growth is exactly
   the length added to the receipt's `path`.
6. **Control on a second endpoint.** `/v1/api/_internal/model-status`: 26,790 B (`head`) vs
   26,794 B (`worker_2`) — again exactly 4.

## Conclusion

A four-byte delta equal to the target-name length, reproduced on two endpoints, with a single shared
registry table and byte-identical node self-reports, is a wrapper artefact. There is no per-node row
or field to reconcile, and **no node was synchronised**.

## Limit of the read

The full per-node bodies cannot be fetched through existing access: the bridge truncates at 18,000
characters and returns no partial body; the nodes require the root-only admin token
(`a root-only admin credential file`, 0600 root:root); and
`GET /v1/api/models/<alias>` does not exist (404 measured). None of these limits changes the
conclusion, because the delta is fully accounted for by the envelope.
