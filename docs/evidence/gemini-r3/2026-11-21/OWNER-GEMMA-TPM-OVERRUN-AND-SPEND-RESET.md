# OWNER BLOCKER — Gemma 26B input-TPM overrun; spend-based 10-minute window DOES NOT apply to Free
2026-11-21 · Switchyard PR #46 follow-on; R3.2 live CURRENT+LKG per Turnstone receipt. Source-level steering, **no extra Google calls or production change authorized**.

## What Google actually says (official vendor reference, independently reopened)

[Google Gemini API rate limits](https://ai.google.dev/gemini-api/docs/rate-limits), under **How rate limits work** and **Spend-based rate limits**:
- Limits are independently evaluated as **requests per minute (RPM)**, **input tokens per minute (TPM)** and **requests per day (RPD)**. Exceeding ANY may produce a rate-limit error. Limits apply **per project**, not per API key; models can have different rate ceilings. RPD resets at **midnight Pacific time**.
- **Spend-based rate limits are a separate rolling 10-minute meter, for paid usage tiers where applicable: Free N/A, Tier 1 $10 / 10 minutes, Tier 2 $200 / 10 minutes, Tier 3 $200 / 10 minutes.** The owner's Free-tier Gemini/Gemma requests do NOT obtain extra minute-token allowance by waiting ten minutes for spend to reset. A spend-based `429 RESOURCE_EXHAUSTED` must be classified only if error details actually prove spend scope; bare `RESOURCE_EXHAUSTED` is ambiguous.
- A rolling ten-minute window is not a synchronized reset every ten minutes: older charges age out; similarly, short RPM/TPM capacity returns as its minute-window activity clears. Google warns published limits do not guarantee capacity.

## Immediate implementation safety contract — smallest patch, no new architecture

1. **Never claim that `chars/4` is precise token admission.** Current `crates/libsy-llm-client/src/allowance.rs::estimate_input_tokens` and `client.rs::send_once` reserve on estimated text. The per-model 60s governor is real but input-token reservations are soft. Cap/sanitize inputs for tight Free TPM models before dispatch. Until proven counting exists, establish a **conservative, owner-configurable admission margin** (e.g., minimum ×1.30 for text *based only on currently observed samples*, not an absolute guarantee). Large/near-limit or tokenization-unknown requests must go to a compatible higher-TPM Free candidate, wait, undergo selectively qualified exact counting, or fail with an accurate local throttle. **Do not send a near-limit Gemma request on an optimistic char estimate.**
2. **Prefer exact counting where warranted, without turning every small request into a Google call.** Use local, model-matched tokenizer if qualified, or Google's native `countTokens` for requests where the cost/latency and API quota implications are explicitly budgeted. Exact preflight is not automatically identical to billed prompt tokens; retain measured overhead margin and record uncertainty. No `countTokens` call is authorized by this note.
3. **Reconcile post-response provider usage** when `prompt_tokens` is reliably reported: adjust same-model minute-ledger actual reservation up to at least observed tokens, including previously underestimated consumption, before admitting later requests. Keep conservative reservation when actual not reported. Preserve already-sent calls as spent even if failed or if the resulting output is empty; do not fake refunds. Account for tool continuation, JSON schema and native thinking/output separately: Free TPM is **input TPM**, not output token quota.
4. **Model-specific eligibility matters.** Gemma 26B/31B each: **30 RPM, 16K input TPM, 14.4K RPD**. Flash-Lite 3.5/3.1 each: **15 RPM, 250K input TPM, 500 RPD**. Share physical-model/project quota across `smart-nt`, `smart_gemini` and group aliases. For a request known to exceed Gemma's safe input headroom, route to a truly capable wide-TPM Lite leaf if permitted; otherwise queue or refuse. Keep Google-only canaries from spilling paid and private/uncleared tasks out of Google before egress.
5. **Respond to actual errors accurately:** per-minute 429 => bounded pace/wait; proven per-model daily quota => model-day block; positively identified project-wide daily quota => shared block; 503 overload => model-specific cooldown. **Do not interpret a spend-based rolling 10-minute 429 as a Free-tier condition** or blindly promise any error clears in exactly ten minutes.
6. **Quality is not HTTP status:** a 200 with empty usable answer and zero completion tokens must be recorded as incomplete task, not successful answer training the selector. Google native thinking remains allowed, never send unsupported no-thinking controls, and hosted `<thought>` must not appear in consumer output.
