Where a provider’s own request id can be found, and what counts as one.

WHY THIS IS SHARED

Two layers need this answer and they must not disagree:

  • the HTTP client, which is the only place a response header still exists and which therefore has to decide whether the error body already names a request;
  • the server, which reads a failed request’s body and reports the id.

When each carried its own list of locations, the writer checked fewer than the reader: a body whose only id was in the provider’s message prose was treated as unnamed, so a header id was injected — and the reader, preferring the structured field, then logged the injected header id instead of the provider’s. One definition, in the crate both depend on, removes that class of divergence.

WHAT A PROVIDER ID IS

Correlation only works if the value is exactly the string the provider logged. A value that has been trimmed of awkward characters, truncated, or otherwise “repaired” is a different string that resolves to no request, and it is worse than reporting nothing because it looks like evidence. So every entry point here validates and refuses; none of them repairs.
